**Finding 2: "SITUATE returned 0 files" dominates.** This is the
canonical pe_chain stuck-point signal. Firing consult there is correct —
it's exactly the "I don't know what to change" case that a peer should
unstick. Keep the trigger.

**Finding 3: `T-test` entries with `GOAL_123` are test-scaffold leakage.**
25 of 104 sessions (24%) have `ticket_id=T-test, pursuit_id=GOAL_123`.
This is test-fixture data polluting the prod log. Two remediations:
- Route consults.log through an `IGOR_TEST_MODE` gate (append `.test`
  suffix when set, like several other logs already do)
- Filter fixture tickets from observe-and-tune analysis by default

**Finding 4: "pre-flight blocked (no recognizer)" is an awkward trigger.**
Every one of these fired on a real ticket but produced a hypothesis like
"the test suite itself is hanging — not your code." The consult didn't
help — the information was unactionable. Candidate for removing the
trigger entirely or gating it on a second signal (e.g., only consult if
pre-flight fails AND git status shows real changes to test-relevant
files).

## Confab-scan correlation

**Finding 5: confab-scan never flagged in 104 consults.** Either (a) the
scan is too conservative (false-negative), (b) the model's responses
genuinely don't confabulate enough to trip it, or (c) the scanner hooks
are not wired into the path that logs consults. Worth a quick check of
the confab-scan call-site; if (c), the existing tell-phrase detection
won't catch failures from this surface.

## Recommendations (file as follow-on tickets)

1. **Raise confidence threshold from 0.3 → 0.55.** One-line change; risk
   is low because nothing in this sample was sub-0.62. If false-positive
   aborts surface, re-tune based on that data.
2. **Gate consults.log behind IGOR_TEST_MODE.** Write `.test` suffix in
   test mode so fixture calls don't contaminate real-log analysis.
3. **Narrow the "pre-flight blocked" trigger.** Require a second signal
   (file-scope overlap with failing test) before firing.
4. **Verify confab-scan wiring for the consult path.** 0/104 is either
   perfect behavior or a dead signal; need to distinguish.

## Note on current tuning

Current tuning is **not broken** — it produces actionable hypotheses in
roughly 60% of calls (the SITUATE-0-files cluster). The issues are
around **efficiency**: 24% test-fixture pollution, 20% unactionable
pre-flight consults. Tuning these three adjustments should bring the
signal-to-noise ratio up without narrowing the useful-case coverage.
