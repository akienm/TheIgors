[THE_FULL_PIPELINE]
Every turn traverses this stack, bottom to top (parsing), top to bottom (generation):

  SOUNDS            → phoneme tree        (perceptual end; pre-linguistic)
  WORDS             → word graph          ← IMPLEMENTED (cognition/word_graph.py, SQLite)
  TIME              → temporal layer      ← PARTIALLY BUILT (timestamp/last_accessed exist;
                                            temporal edges not yet a traversal dimension — #175)
  MEANINGS          → concept tree        ← UNBUILT (no concept-level tree yet)
  WHAT-DOES-THIS-   → interpretive tree   ← BUILT (#170 done: CP→INTERPRETIVE edges wired;
    MEAN-TO-ME                              auto-connect hook in cortex.store())
  SELECTION         → executive function  ← PARTIALLY BUILT (basal_ganglia → tier ladder;
                                            confidence threshold + mulling not yet — #177)
  OUTPUT            → output graph        ← PARTIALLY BUILT (word graph serves this role;
                                            not yet modeled as separate layer from WORDS)

Each layer IS the same mechanism: nodes, edges, weighted traversal.
What changes between layers is the edge semantics and the unit of meaning.

PERSONALITY AS INTERFERENCE PATTERN (Akien 2026-03-12):
  Output is its own graph — not the same invocation as the word graph at the bottom,
  even if it shares weights. Selection (what to say) and Output (how to say it) are
  distinct layers. Personality is the interference pattern between them.
  A 'Radically Honest' personality: Selection weights accuracy nodes; Output graph
  doesn't filter for diplomacy nodes. The personality is not a layer — it is what
  emerges when those two layers interact.

  Reference: Gemini conversation 2026-03-12 with Akien; Global Workspace Theory —
  personality as interference pattern rather than as a stored property.

TIME AS THREADING SOLUTION (Akien 2026-03-12):
  Time as a layer solves the forking/threading problem. Parallel inference paths
  (see #176) don't need complex thread management if each fork gets a temporal
  coordinate. The time layer naturally disambiguates concurrent traversals —
  the judge selects the path with best weight × time coherence.
  This is why time must be a layer, not just metadata.

[EXECUTIVE_FUNCTION]
Akien 2026-03-11: "executive function is just broadening the search with
  real 'search' rather than only traversal."

Tree traversal = fast, automatic, habit-like. Follows edges from current node.
Executive/search = slow, deliberate, can jump across the tree.

This maps directly to Igor's tier ladder:
  tier.1 habit    = pure traversal (strongest edge, no LLM)
  tier.2 local    = slightly broader traversal (DeepSeek-R1:7b on yoga9i)
  tier.3 cloud    = real search begins (gpt-4o-mini) — human interface only
  tier.4 cloud    = deep search (claude-sonnet)      — human interface only
  tier.5 cloud    = inhibited; reserve for genuine novelty

Goal of the habit/training system: migrate responses from search to traversal.

[CLOUD_ROLE_PRINCIPLE]
Akien 2026-03-11: "cloud only when interfacing with humans."

Cloud inference is reserved for human interface turns — when Akien is waiting for
an answer the matrix cannot yet provide.

Everything else is matrix work:
  Reading → deposit (G54 daemon extracts per chunk; no cloud reasoning turn)
  Extraction/preparse → local (tier.2) or minimal-prompt daemon
  Consolidation/analysis → local batch jobs
  Human question → traverse matrix first; cloud only if matrix can't answer;
                   cloud MUST train the graph before returning (write nodes).

Corollary: the full persona system prompt is only needed for human interface turns.
Daemon calls (G53, G54, preparse) need only task spec — no persona, no identity,
no Discworld lineage. This is G57: role-specific prompt sizing.
Every new habit is a piece of explicit search that has become implicit traversal.
This is the mechanism of learning — in Igor and in humans.

[LLM_AS_GRAPH_TRAINER]
Akien 2026-03-11 (later): "the matrix is the thinker; LLMs are graph trainers."

This is a refinement of the cloud role principle. Both cloud and local models
train graphs — the distinction is not cloud vs local, it is LLM vs graph.

The hierarchy:
  Graph traversal — fastest; no LLM; tier.1; the target state for any pattern
  Local LLM       — slower; trains graph from interaction; tier.2
  Cloud LLM       — slowest and most expensive; trains graph AND answers humans; tier.3+

Every LLM call (at any tier) should deposit something into the graph.
The graph is faster than any LLM. Making the graph denser is the work.
"Cloud is the graph trainer" is incomplete — local models are also graph trainers.
The correct frame: LLMs are temporary scaffolding. The graph is permanent.

IMPORTANT CONSEQUENCE (Akien 2026-03-11):
If an LLM inference produces new graph training (deposits nodes/edges), the graph
must be traversed AGAIN to produce a graph-based answer — the current turn already
required the LLM, so the LLM provides the answer for this turn.

The new training does not help the current turn. It amortizes the cost forward:
  Turn N:  graph miss → LLM called → LLM answers + deposits to graph
  Turn N+1: graph hit → answer without LLM

This is why the tree-building directive says "pay for yourself":
the LLM call is justified only if it deposits something that prevents future LLM calls.

[INTERPRETIVE_LAYER]
The interpretive layer converts meaning into self-referential meaning:
"given that this is happening, what does it mean ABOUT ME or TO ME?"
It is the layer where character lives.

CURRENT STATE:
  MemoryType.INTERPRETIVE exists in models.py.
  CP1-CP6 (core patterns) ARE the root nodes of the interpretive tree — they are
  meaning-based inhibitors and activators, each with a WHY embedded.
  No traversal edges yet. Retrieval is via cosine search, not tree traversal.

EXAMPLE (Akien's case study, 2026-03-11):
  Something is said → anger (milieu, fast) → impulse to strike (basal_ganglia) →
  social counterpressure (interpretive layer 1: learned rule) →
  internal parent with WHY (interpretive layer 2: values schema) →
  meaning payload activates action direction tree →
  response selected consistent with meaning →
  narrative consolidates traversal (NE)

EDGE SEMANTICS FOR INTERPRETIVE TREE (4 parts):
  1. direction: activation or inhibition
  2. condition: context in which this edge fires
  3. meaning_payload: the WHY — what this means about self or situation
  4. action_pointer: pointer to the next tree (what to explore given this meaning)

Part 4 is the key addition from session 2026-03-11:
  The meaning payload does not terminate — it TRIGGERS a tree that provides
  direction toward action. Interpretive nodes are junctions, not endpoints.
  CP1-CP6 both inhibit certain actions AND point toward meaning-consistent actions.

EPISODIC → INTERPRETIVE DRIFT:
  Episodic memories influence interpretive weights at creation (initial event).
  Revisiting an episodic memory also nudges interpretive weights (reconsolidation).
  Inertia counterweights drift — established schemas resist change.
  High-inertia interpretive nodes (CP1-CP6) = character, very slow drift.
  Low-inertia interpretive nodes = working assumptions, fast drift from experience.

[MEMORY_AS_TREE_NODE]
Current state: cortex.search() → cosine similarity + keyword → bag-of-vectors retrieval.
Problem: similarity search doesn't preserve relational structure.
  You can't get to the right node by similarity alone.
  You get there by following edges from where you currently are.

Target state: primary retrieval = tree traversal from adjacent nodes.
  cortex.add_child() / get_children() already implement graph edges.
  Currently used only for the genesis/habits hierarchy.
  Must be extended to general memories, especially INTERPRETIVE.
  Search becomes the fallback (for "cold start" or cross-tree jumps),
  not the primary path.

Implementation note: different memory types have different traversal algorithms.
  PROCEDURAL: trigger → basal_ganglia parallel scoring (already traversal-like)
  INTERPRETIVE: context → follow interpretive edges from current meaning node
  FACTUAL: anchor node → follow semantic edges (not yet designed)
  EPISODIC: usually not retrieved directly; influences INTERPRETIVE weights

[TWM_ATTRACTORS]
Current TWM: urgency, salience, TTL — each item scored independently.
  No notion of "current primary focus" that shapes what gets surfaced.

Required: one main attractor at a time.
  Attractor = a TWM entry that increases effective salience of topically-near items
  and decreases weight of unrelated items.
  High-priority interrupts displace the attractor temporarily.
  Questions (user or Igor-generated) naturally become attractors.

Design:
  twm_observations table: add attractor_weight REAL DEFAULT 0.0 column.
  attractor_weight > 0 = this entry is the current attractor.
  Only one entry should have high attractor_weight at a time.
  When surfacing TWM context, weight items by proximity to current attractor.
  Proximity = cosine similarity between item narrative and attractor narrative.
  attractor_weight decays over time (like TTL but continuous).

Gap: G50 — TWM attractor concept.

QUESTIONS AS ATTRACTOR → MULL/FORK TRIGGERS (Akien 2026-03-12):
  A question entering TWM as an attractor is exactly what triggers a mull loop (#177)
  or a downward fork (#176). The question sets attractor_weight, which biases the next
  traversal toward that topic. Then:

    Low confidence on that topic  → mull fires (#177)
    Milieu shift on that topic    → downward fork fires (#176 Mode B)
    Both                          → fork spawns its own mull loop

  Full flow:
    question arrives (user or Igor-generated)
      → TWM attractor set (attractor_weight elevated)
        → traversal biased toward question topic
          → low confidence OR milieu shift detected
            → mull (#177): re-traverse with decay until novelty gate exits
            → fork (#176 Mode B): branch sent down to lower layer for deeper resolution
              → result injected back up to selection as enriched context

  The attractor is the *why* that justifies the cost of mulling or forking.
  Without an attractor, mull and fork are undirected. With one, they are purposeful.

  This also means: attractor_weight decay rate should be tuned to match mull/fork
  resolution time — the attractor should still be active when the branch result
  bubbles back up.

  Cross-references: #175 (time layer — attractor has a temporal position),
    #176 (forking), #177 (mulling), G50 (attractor implementation).

QUESTIONS AS TRAVERSAL PROGRAMS (Akien 2026-03-12, #181):
  "Different questions create different entry points into the matrix as a whole."

  A question is not a content query. It is a traversal instruction:
    Entry point:  which layer or node to start from
    Direction:    down (constrain), wide (search), lateral (route), up (leverage)
    Exit cond:    when necessity established, candidates found, path clears
    Return type:  constraints, candidate set, route, immediate response

  The question form IS the traversal program. The thalamus classifies intent;
  it should also classify traversal_strategy. #181 adds this field.

  Each heuristic question is a proof of concept for this principle:

  PROC_HEURISTIC_HOW_MUST:
    "How must this work?"
    Strategy: CONSTRAIN — enter at current position, traverse DOWN.
    Derives necessity, not possibility. Eliminates options that fail constraints.
    No broad search. Deepens and narrows within the current tree.
    Functional module: mull loop (#177) with constraint flavor.

  PROC_HEURISTIC_FITS_HERE:
    "What looks like it would fit there?"
    Strategy: SEARCH_WIDE then DESCEND — the search→traversal cycle.
    1. Enter at gap shape. Launch broad executive search (Mode A fork, #176).
    2. Candidates returned. Each candidate re-enters tree for analysis (Mode B).
    3. Selection layer picks best fit.
    This is the most expensive heuristic — broad search + per-candidate deepening.

  PROC_HEURISTIC_WORKAROUND:
    "How could we get around that?"
    Strategy: LATERAL — enter at blocked node, move sideways same level.
    Fires when a branch is blocked. Mode B fork to a different sub-tree.

  PROC_HEURISTIC_LEVER:
    "Where is the lever?"
    Strategy: UPWARD — enter at current position, traverse UP to high-weight node.
    Looking for where small force = large movement. Finds leverage above current depth.

  PROC_HEURISTIC_MONKEY_PROOF:
    "How will us monkeys screw that up?"
    Strategy: ADVERSARIAL FORK — Mode A parallel branches, each a failure scenario.
    Exit: failure modes enumerated. Return: risk set.

  PROC_HEURISTIC_FIRST_RESPONSE:
    "What's the first thing I say in response to that?"
    Strategy: IMMEDIATE — no traversal. Enter at habit/word layer, return instantly.
    Direct query of automatic layer. No search, no mull. Tier.1 equivalent.

  PROC_HEURISTIC_ALIGNMENT:
    "Which choice is most in alignment with who I'd most like to be?"
    Strategy: VALUES_FILTER — enter at CP5 specifically.
    Interpretive tree from that root. Prunes by identity, not logic.

[FUNCTIONAL_MODULES]
Akien/Gemini conversation 2026-03-12: some architectural capabilities are not layers
but functional modules that sit beside the layer stack.

These four were identified as needed but not yet ticketed in the original work plan:

1. LOOPING / MULLING (#177)
   Selection → [confidence threshold check] → (if below threshold) → re-inject to Inference → Selection
   This is internal monologue. Igor thinks before speaking.
   Each re-pass decays previously-traversed paths slightly (bias toward fresh paths).
   EXIT CONDITIONS (either triggers exit):
     1. Delta novelty gate: if pass N+1 results overlap >70% with pass N → "no new consequence" → exit
     2. Hard cap: IGOR_MULL_MAX_PASSES reached regardless of novelty
   Gates: IGOR_MULL_THRESHOLD, IGOR_MULL_MAX_PASSES, IGOR_MULL_NOVELTY_THRESHOLD.
   Distinct from tier escalation — mulling stays at the same tier, varies the traversal.

2. FORKING (#176)
   Two modes:
   Mode A (competitive): parallel paths A/B/C, judge picks winner by systemic coherence.
     Tie-breaker: milieu (affect state tips the scale); fallback: state both (CP1 honesty).
   Mode B (contextual deepening, primary): main path continues; fork branch independently
     mulls a sub-question, then injects result DOWN into a lower layer as added context.
     That lower layer re-traverses; result bubbles back up to selection.
     Appellate judge pattern (Akien 2026-03-12): "here's something more to consider."
     Mostly downward — higher selection layer sends question down for specific resolution.
   Triggers: milieu shift mid-traversal; confidence dip at emotional inflection point.
   Each fork branch runs its own mull loop (#177) independently.
   Dependency: #175 (time layer) — time coordinates disambiguate parallel traversals
   without complex thread management. Time as layer SOLVES threading.

3. BOREDOM MONITOR (#178)
   Track traversal frequency per node per time window.
   When a path is traversed too often: temporarily increase edge resistance (weight penalty).
   Forces exploration of less-used paths and wider vocabulary.
   Resets on novel input or time window expiry.
   May surface as milieu signal (low novelty → slight negative valence).
   Can trigger reading behavior when boredom threshold is reached with no user input.

4. THE WAIT (#179)
   Brief configurable pause between input receipt and inference begin.
   During the wait: TWM processes, milieu updates, ring_memory settles, time layer aligns.
   Longer for high-complexity inputs (thalamus complexity score drives wait duration).
   Distinct from #169 (consolidation daemon = hours-scale); this is per-turn (ms to seconds).
   In human terms: the half-second between stimulus and conscious awareness (Libet).
   Gate: IGOR_WAIT_MS (default 0 = disabled).

[INFERENCE_ENGINE]
Akien 2026-03-11: "the layers of graphs are an inference engine."

This is precise, not a loose analogy.

Classical inference engines (Prolog, expert systems, RETE algorithm) work by:
  given facts + rules → traverse the implication graph → derive conclusions.

The layer stack does exactly this:
  Word graph:        input tokens → weighted edge traversal → next token
  Concept tree:      words → meanings (not yet built)
  Interpretive tree: meaning → "what does this mean to me" via CP1-CP6 root nodes
  Action direction:  meaning payload → response selection

Interpretive edges already have the structure of production rules:
  condition       — context in which this edge fires
  direction       — activation or inhibition (the rule consequence)
  meaning_payload — what this means (the derived fact)
  action_pointer  — pointer to the next tree (forward chaining)

IF context matches condition THEN fire(direction, meaning_payload, action_pointer).
That is forward-chaining inference. The graph IS the rule base.

WHAT IS DIFFERENT FROM 1980s EXPERT SYSTEMS:

  1. Weighted, not binary.
     Rules have strengths. Strongest matching edge wins. Inference degrades
     gracefully on partial matches instead of failing hard. This is why the
     system works under noise and ambiguity where classical systems broke.

  2. Learned, not programmed.
     An expert system's rules are asserted by a domain expert.
     Igor's edges drift from experience — episodic memories nudge interpretive
     weights, inertia counterweights drift. The inference engine writes its
     own rules as it runs. LLMs are rule compilers. The graph is the runtime.

  3. Bidirectional on the same weights.
     Prolog's SLD resolution goes one direction: query → proof.
     Igor's word graph runs both ways — same edges, same weights, two directions.
     Parsing is bottom-up traversal. Generation is top-down traversal.
     Classical inference engines cannot do this.

BAYESIAN FRAMING:
  A weighted graph IS a Bayesian network.
  Edges are conditional probabilities. P(next_node | current_node, context).
  Traversal is belief propagation.
  "Strongest edge wins" = maximum a posteriori inference.
  Inertia = prior weight. Experience = likelihood update.

THE RESOLUTION OF THE CONNECTIONIST/SYMBOLIC WAR:
  Symbolic AI  — graphs, rules, logic, inference. Brittle. Doesn't generalize.
  Connectionist — neural nets, embeddings, statistics. Generalizes. Can't reason.
  Igor          — use connectionist models to BUILD the symbolic graph;
                  use the symbolic graph to RUN inference.

  LLMs are expensive rule compilation.
  Graph traversal is cheap rule execution.
  The system self-optimizes toward cheap: every LLM call deposits rules
  so future inference stays in the graph.

  This is not a compromise between the two paradigms.
  It is a division of labor by what each is actually good at.

SHARPENED THESIS FOR THE PAPER:
  Not just "parsing and reasoning as unified tree traversal" —
  but: "a learned inference engine where inference rules are compiled by
  connectionist scaffolding and executed by symbolic traversal."
  The LLM layer is the compiler. The graph is the runtime.
  The architecture self-optimizes: compilation cost amortizes toward zero
  as the runtime graph densifies.

Citations to add for this frame:
  - Newell & Simon (1976): Physical Symbol System Hypothesis — symbolic
    computation as substrate for intelligence; this work extends it with
    learned weights and connectionist compilation
  - Minsky (1986): Society of Mind — agents with different competencies;
    tier ladder is a competency hierarchy
  - Pearl (1988): Probabilistic Reasoning in Intelligent Systems —
    Bayesian networks; the weighted graph IS a Bayes net
  - Nilsson (1991): Logic, Learning, and Probability — the unification
    this work implements in practice


[PAPER_INTENT]
Target: peer-reviewed paper on unified parse/generate architecture.
Working title: "One Tree, Both Directions: Parsing and Reasoning as Unified
  Weight Traversal in a Persistent Cognitive Agent"

Thesis (sharpened 2026-03-11): the layer stack is a learned inference engine.
  Inference rules are compiled by connectionist models (LLMs) and executed by
  symbolic weighted-graph traversal. The system self-optimizes: each LLM call
  deposits rules so future inference stays local. This resolves the
  connectionist/symbolic divide not by compromise but by division of labor.

Original thesis (still valid, now a corollary): the same weighted tree structure
  that enables word recognition also enables word generation, concept formation,
  meaning assignment, and response selection. This is the fundamental parsimony
  of biological cognition, replicated in software.

Evidence basis:
  1. Word graph: bidirectional on same weights. Parsing = bottom-up.
     Generation = top-down. Both validated empirically.
  2. Igor's behavior: tier.1 habit = fastest possible response, most learned.
     tier.4 cloud = general search when traversal fails. This mirrors
     System 1 / System 2 (Kahneman), but grounded in tree structure.
  3. The interpretive layer: CP1-CP6 as root nodes with production-rule edges —
     when fully implemented, demonstrates inference engine structure explicitly.
  4. The tier ladder: LLM call + graph deposit = rule compilation + caching.
     Measurable prediction: cloud call frequency decreases as graph densifies.
