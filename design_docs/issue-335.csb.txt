TITLE|Unified memory schema — START_AT and temporal anchoring
RELATES|subsystem_memory.dsb, memory/models.py (HIGH inertia)

PROBLEM|
  Memory nodes have no consistent temporal anchoring for the *content* they describe.
  `timestamp` = when the memory was stored, not when the event occurred.
  For episodic memories and factual knowledge, the distinction matters.
  Example: memory of a 2024 event stored in 2026 — search context shows "stored 0d ago"
  but the content is 2 years stale. Igor can be confused about event timing.

  Also: the episodic-to-semantic merge design (#250) needs a temporal anchor to aggregate
  "occurrence_dates" — currently there's no canonical field to put this.

DESIGN|
  Add `start_at` (not `start_index`) to memory schema:
    - Nullable TIMESTAMP
    - Meaning: "when did the event/fact described by this memory begin?"
    - For episodic: set to event start time
    - For factual: set to publication/observation date if known
    - For procedural/interpretive: NULL (timeless)

  KEY_NAME_DECISION: field is called `start_at` not `start_index` or `started_at`.
  Rationale: `at` suffix = point in time; consistent with `closed_at` in trail_metadata.
  `started_at` reads as "when this node was started" (ambiguous with storage time).
  `start_at` reads as "the start time of the content", distinct from `timestamp` (storage).

TEMPORAL_CONTEXT_INJECTION|
  DP10 already injects temporal context into ring entries (YYYY-MM-DD HH:MM for non-today).
  Extension: if memory.start_at is set AND differs from timestamp significantly,
  inject both: "stored Xd ago; describes event from YYYY-MM-DD"
  Prevents Igor confusing storage time with event time.

OCCURRENCE_DATES|
  For the episodic-to-semantic merge (#250, not yet implemented):
  metadata.occurrence_dates = list of ISO timestamps when this pattern was observed.
  start_at = first occurrence (min of occurrence_dates).
  This is a metadata field, not a schema column — avoids HIGH-inertia schema change
  until the merge design is fully validated.

INERTIA_WARNING|
  memory/models.py is HIGH inertia. Adding `start_at` column requires:
  - Migration in cortex._init_db()
  - Update to Memory dataclass in models.py
  - Update to _PG_SCHEMA string (Postgres)
  Scope is small but touches HIGH-inertia files. Requires Akien review before worker.

MIGRATION|
  ALTER TABLE memories ADD COLUMN IF NOT EXISTS start_at TIMESTAMP;
  Named migration: "memories_v3_start_at"
  Default: NULL for existing rows (backward compatible).

OPEN_QUESTIONS|
  Q1: Should WG nodes (word_graph.db) also get start_at?
      Answer: No — word graph is statistical, not episodic. start_at doesn't apply.
  Q2: Should start_at be indexed?
      Answer: Yes — idx_memories_start_at for temporal range queries (find memories
      about events in a date range). Add at migration time.
  Q3: Does this interact with D045 temporal context injection?
      Answer: Yes — see TEMPORAL_CONTEXT_INJECTION above. Extend, don't replace.
