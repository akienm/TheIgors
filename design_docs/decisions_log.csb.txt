# ── D018 — Reasoning Cache with TWM Watermark Invalidation ────────────────────

DECISION|id=D018|topic=reasoning-cache|status=implemented|change=cache.2
TITLE|File-backed TTL+watermark cache for Ollama NE reasoning calls
CONTEXT|NarrativeEngine fires every 30s-5min; if TWM hasn't changed since last run, Ollama call repeats the same prompt for the same answer; pure wasted latency on quiet sessions
DECISION|cognition/reasoning_cache.py; key=sha256(model+prompt); TTL=12min; invalidated when current_max_twm_id > stored watermark; cache files at ~/.TheIgors/cache/reasoning/
RATIONALE|TTL alone is insufficient: a 12-minute cache on a busy session would serve stale responses; TWM watermark is the correct semantic invalidation signal — "new observations arrived → reasoning may differ"
RATIONALE|max_twm_id is already in hand from obs_list that was read before the Ollama call — no extra DB query needed; zero overhead on cache-miss path
RATIONALE|Complements embedding cache (D013/cache.1): embeddings cached on vector content, reasoning cached on prompt+TWM state; different invalidation signals for different content types
ALTERNATIVES|Rejected: no cache (current state — wastes Ollama latency on quiet sessions); hash-only cache (no TTL — never evicts even if hours old); in-memory cache (lost on restart)
TRADEOFFS|Cache file accumulates over time; stale entries evicted only on next access (lazy); acceptable for this use pattern; can add periodic sweep later if needed
NOTE|Only NE benefits significantly — preparse/score_memories are per-user-message (inherently unique), hit rate near zero there

# ── D017 — Hybrid Embedding Search in cortex.search() ────────────────────────

DECISION|id=D017|topic=hybrid-embedding-search|status=implemented|change=37
TITLE|Two-phase search: text keyword scan → embedding re-rank via nomic-embed-text
CONTEXT|cortex.search() was naive text keyword matching sorted by activation_count; poor retrieval quality for paraphrase or conceptual matches
DECISION|Phase1: text keyword scan → limit×2 candidates; Phase2: embed query + lazy-compute candidate embeddings → cosine_similarity sort; sets m.relevance_score on results; fallback to Phase1 if Ollama unavailable
RATIONALE|Phase1 (fast text scan) narrows to plausible candidates; Phase2 (semantic cosine) reranks by meaning not just lexical overlap; hybrid avoids the cold-start cost of embedding everything
RATIONALE|Lazy embedding: 422 existing memories computed on-demand as they surface as candidates; avoids a one-time ~21s blocking migration at boot; results cached to DB for future calls
RATIONALE|relevance_score field enables AnthropicReasoner to filter memories below threshold (≥0.5) rather than using top-N blindly
ALTERNATIVES|Rejected: pure embedding search (requires vectorizing all memories first; cold start on 422 entries); FAISS/vector DB (adds heavy dependency; overkill for 422-10k memories); BM25 only (better than raw keyword but still no semantic cross-vocabulary)
TRADEOFFS|First access to each memory is slower (embed compute); subsequent calls are DB-cache hits; Phase2 adds one Ollama call per search when uncached embeddings present; degrades gracefully if Ollama offline

# ── D016 — Arbiter: File-Backed Human Approval Queue ─────────────────────────

DECISION|id=D016|topic=arbiter-queue|status=implemented|change=33
TITLE|File-backed JSON queue for human approval of irreversible/uncertain actions
CONTEXT|Igor's NE proposes action impulses; some are irreversible (delete, send, publish, deploy) or ethically uncertain; executing without review violates CP6 (active safety) and risks unintended side effects
DECISION|arbiter/queue.py; QUEUE_FILE=~/.TheIgors/igor_wild_0001/arbiter/pending.json; is_irreversible_impulse() keyword scan gates NE impulses; ethics_gate failures also submit; akien reviews via /arbiter or conversational "approve"/"deny"
RATIONALE|File-backed not DB-backed: queue is small (typically 0-5 items), must survive restarts, and is akien-inspectable with a text editor; DB adds no benefit here
RATIONALE|Non-blocking: Igor continues while items queue; akien can approve/deny async; one Discord ping per item prevents alert fatigue
RATIONALE|Learning loop: approve/deny decisions stored as EPISODIC memories with valence ±0.7; after consistent patterns → /habits pending → habit compilation; queue shrinks as Igor learns akien's threshold
RATIONALE|Conversational intercept in _process(): "approve"/"yes"/"ok" captured before habit/basal-ganglia matching when pending items exist; reduces UX friction of formal /arbiter syntax
ALTERNATIVES|Rejected: block execution until approved (too disruptive to Igor's flow); no queue (NE impulses silently dropped — current state before change.33); DB-backed queue (overkill for small N)
TRADEOFFS|File I/O on every submit/resolve; acceptable for low-frequency arbiter events; JSON file is human-readable audit trail

# ── D015 — Gateway Pattern: Igor Owns All State ───────────────────────────────

DECISION|id=D015|topic=gateway-pattern|status=implemented|change=30
TITLE|Igor class is the sole owner of runtime state; interfaces hold no state references
CONTEXT|web/server.py held `_cortex = None` module-level var; `_api_dashboard` called `_cortex.total_count()` directly; `update_stats()` was a push from `_process()` every interaction
DECISION|Add `Igor.get_stats() → dict`; pass `stats_fn=self.get_stats` to `web_server.start()`; `/api/dashboard` calls `stats_fn()`; remove `_cortex` from server.py and `update_stats()` entirely
RATIONALE|Igor.cortex is internal state — exposing it to web server creates cross-module coupling that is hard to test, refactor, or version independently
RATIONALE|Pull model (dashboard polls `stats_fn()`) is simpler than push model (Igor pushes on every interaction); live values without push/pull race conditions
RATIONALE|Prepares for change.33 (arbiter) and change.35-36 (network) which will add more interfaces; clean boundary now prevents proliferation of direct state access
ALTERNATIVES|Rejected: keep `_cortex` in server.py (existing coupling); keep `update_stats()` push with cortex removed (hybrid still couples push timing to `_process()`)
TRADEOFFS|`/api/dashboard` now calls `cortex.total_count()` on every HTTP poll (5s); negligible cost for SQLite COUNT(*)
NOTE|discord_bot.py was already clean — no cortex access; only web/server.py needed the fix

# ── D014 — Canonical Ring Injection Point ─────────────────────────────────────

DECISION|id=D014|topic=ring-injection-ownership|status=implemented
TITLE|anthropic.py owns ring context injection; main.py does not inject ring entries
CONTEXT|main.py built ring_ctx (10 entries) and prepended to user input; anthropic.py._build_session_context() independently read 5 ring entries when cortex available; net effect: double injection with conflicting format when both active
DECISION|Remove ring_ctx from main.py._process(); pass cortex through pfc.reason() → reasoner.reason(); anthropic.py injects exactly RING_CONTEXT_LIMIT=5 filtered ring entries via _build_session_context()
RATIONALE|Single canonical injection point eliminates duplication and format conflicts
RATIONALE|anthropic.py already had correct filtering logic (excludes tool_trace, judgment categories); main.py did not filter
RATIONALE|OllamaReasoner (local pool) does not use ring context — correct, as small local models are not built for it
ALTERNATIVES|Rejected: keep main.py injection, disable anthropic.py — would lose category filtering and cortex passing
TRADEOFFS|pfc.reason() now has cortex parameter (minor API surface growth); OllamaReasoner.reason() receives cortex=None (no-op)
NOTE|anthropic.py._build_session_context() uses RING_CONTEXT_LIMIT=5 with category filter; this is the only ring injection into Claude API calls

# ── D013 — Single Embedding Model Across Cluster ──────────────────────────────

DECISION|id=D013|topic=single-embedding-model|status=implemented|change=37
TITLE|nomic-embed-text as universal embedding model across LAN cluster
CONTEXT|Semantic search across all Ollama machines requires consistent embedding space; naive text search was insufficient
DECISION|All cluster machines run nomic-embed-text; embeddings cached at ~/.TheIgors/cache/embeddings/; cortex.search() uses hybrid text→embedding pipeline; boot_check.py verifies + pulls model on startup
RATIONALE|Cross-machine similarity search requires identical embedding dimensions and tokenization
RATIONALE|Embedding space mismatch bugs are subtle and hard to detect post-deployment
RATIONALE|nomic-embed-text: open-source, CPU-capable, good retrieval quality, Apache licensed
ALTERNATIVES|Rejected: per-machine model selection (incompatible spaces); OpenAI embeddings (cost + privacy)
TRADEOFFS|Requires all machines to pull model at boot; adds ~270MB disk per machine; first embedding call per memory is slow; subsequent are cache hits

# ── D011 — Base-34 Instance IDs ───────────────────────────────────────────────

DECISION|id=D011|topic=base34-instance-ids|status=defined|implementation=partial
TITLE|Base-34 encoded epoch seconds for Igor instance identifiers
CONTEXT|Need short, human-readable, collision-resistant identifiers for distributed instances
DECISION|Charset: 23456789ABCDEFGHIJKLMNOPQRSTUVWXYZ (34 chars); encode Unix timestamp at genesis
RATIONALE|Excludes 0/1 to avoid O/I/l/0 visual ambiguity in filenames, logs, and verbal communication
RATIONALE|Epoch seconds gives temporal ordering; base-34 encoding shortens to ~6-7 chars
RATIONALE|wild- prefix for local hardware; claude- prefix for hosted instances
ALTERNATIVES|Rejected: UUID (too long, no ordering, visually ambiguous); sequential int (collision across machines)
NOTE|wild-0001 is development shorthand — not actually base-34 encoded; production instances will use encoding

# ── D009 — Daemon Threads for Background Services ─────────────────────────────

DECISION|id=D009|topic=daemon-threads-for-background|status=implemented
TITLE|Background services run in daemon threads with their own asyncio loops
CONTEXT|Discord bot, web server, narrative engine must run concurrently with REPL without blocking it
DECISION|Each service: threading.Thread(daemon=True) + asyncio.run() inside the thread
RATIONALE|Daemon threads die automatically when main thread exits — no cleanup code needed
RATIONALE|Each service gets own asyncio event loop; eliminates shared-loop coordination issues
RATIONALE|Thread-safe queue.Queue bridges between threads; simple and well-understood
ALTERNATIVES|Rejected: asyncio tasks in main loop (REPL stdin.read() blocks); multiprocessing (IPC overhead)
SERVICES_USING|discord_bot.py, web/server.py, narrative_engine.py

# ── D006 — CSB Format ─────────────────────────────────────────────────────────

DECISION|id=D006|topic=csb-format|status=implemented
TITLE|CSB (Compressed Semantic Block) pipe-delimited format throughout Igor
CONTEXT|Need dense structured data for TWM observations, ring memory, logs, documentation
DECISION|Pipe-delimited positional or key=value fields; human-readable, machine-parseable via split('|')
RATIONALE|JSON overhead (brackets, quotes, escaping) adds noise in dense observation streams
RATIONALE|Works inline in Claude prompt text without confusing the model's parsing
RATIONALE|Consistent format across all layers: push sources, ring_memory, changes.log, design_docs
ALTERNATIVES|Rejected: JSON (verbose, quote-escape friction); YAML (indentation-sensitive); CSV (commas in content)
USED_IN|twm_push() content_csb, ring_push() entries, all push sources, all design_docs/*.csb.txt

# ── D005 — Inertia from Network Position ──────────────────────────────────────

DECISION|id=D005|topic=inertia-from-network-position|status=implemented
TITLE|Inertia computed from graph structure and activation history, not declared as a field
CONTEXT|Need resistance-to-change that honestly reflects actual importance in knowledge graph
DECISION|inertia = f(memory_type_base, activation_count, children_count, depth_from_root)
RATIONALE|Inertia that emerges from use patterns is epistemically honest — earned, not assigned
RATIONALE|Prevents gaming: cannot set inertia=1.0 arbitrarily; must earn resistance through activation
RATIONALE|Brainstem memories (type base=0.9) start high and grow; episodic starts low and stays low
ALTERNATIVES|Rejected: declared inertia field (gameable, requires maintenance); uniform inertia (no differentiation)
NOTE|inertia_override optional field exists in models.py for exceptional cases; rarely used

DECISION|id=D004|topic=sqlite-not-json|status=implemented
TITLE|SQLite for all persistent state; no JSON files for runtime data
CONTEXT|Need persistent memory that survives restarts, supports complex queries, prevents corruption
DECISION|SQLite for memories, ring_memory, twm_observations, budget; no JSON state files

FILES|wild_igor/data/wild-0001.db (memories, ring, twm), wild_igor/data/claude_budget.db (tokens)

# ── D001 — Everything Is a Memory ────────────────────────────────────────────

DECISION|id=D001|topic=everything-is-memory|status=implemented
TITLE|All knowledge stored as Memory objects in SQLite graph; no separate config or rules files
CONTEXT|Need persistent, self-modifiable knowledge store that survives restarts and supports inference
DECISION|Store ALL knowledge as Memory objects: ethics (CORE_PATTERN), identity (IDENTITY), procedures (PROCEDURAL), facts (FACTUAL), events (EPISODIC)
RATIONALE|Uniform representation enables uniform operations: inertia, valence, activation, graph traversal
RATIONALE|Self-modification IS memory modification — no separate "rules file" to bypass or forget to update
RATIONALE|Graph structure (parent_id + adjacency) enables inertia propagation, context clustering, spreading activation (planned)
RATIONALE|Inertia naturally varies by type: ethics resist change more than episodic events
ALTERNATIVES|Rejected: JSON config (not queryable, not self-modifying, static); Python constants (frozen, no activation tracking)
IMPLICATION|Everything Igor knows about itself, its ethics, its procedures lives in the same queryable space it reasons over
STATUS|implemented|db: wild_igor/data/wild-0001.db (~422+ memories as of 2026-02)
