# ── D024 — observe() Self-Instrumentation Primitive ──────────────────────────

DECISION|id=D024|topic=self-instrumentation|status=implemented|date=2026-03-01
TITLE|observe() as the dynamic self-instrumentation layer alongside static forensic logs
CONTEXT|Forensic logs (WO3) are static — we decide what to log, they record it, we read it. But Igor needs a way to instrument himself where he notices friction, and for those observations to compile into habits over time
DECISION|cognition/observer.py: observe(label, value, context) → metrics.log + EXPERIENTIAL memory; init(cortex) wired at boot; never raises; Igor places calls himself; self-edit lets him add new call-sites
RATIONALE|Two distinct layers serve two distinct audiences: forensic logs = us debugging Igor; observe() = Igor debugging himself. Same infrastructure, different semantics and ownership
RATIONALE|EXPERIENTIAL memories (salience 0.2) are low-noise — they inform retrieval and habit compilation without dominating responses
RATIONALE|Auto-detecting caller via inspect.stack()[1] keeps call sites minimal — observe("tier_selected", "tier.3", {...}) with no manual provenance boilerplate
ALTERNATIVES|Rejected: adding more fields to forensic log (mixes our instrumentation with Igor's; no path to habit compilation); TWM-only (no persistence; lost between sessions)
TRADEOFFS|inspect.stack() has minor overhead; acceptable at observe() frequency; swallowed on failure so never blocks main loop

# ── D023 — Adaptive Routing: Benchmark + Latency Budget + RoutingWeights ──────

DECISION|id=D023|topic=adaptive-routing|status=implemented|date=2026-03-01
TITLE|Boot benchmarking, latency budget enforcement, and session-scoped routing weight adjustment
CONTEXT|gemma3:1b is slow on some hardware (7+ tok/sec → 8-15s for typical prompts); routing only optimized for complexity, not speed or cost; no signal that user was frustrated by latency
DECISION|Part A: _run_benchmark() measures tokens/sec via 3 short prompts; cached 24h per machine at ~/.TheIgors/benchmarks/{hostname}.json; async daemon thread — no startup delay; Part B: LocalOllamaPool.reason() estimates latency before committing; raises if >LATENCY_BUDGET_SECONDS to trigger cloud escalation; logs est+actual+scores; Part C: RoutingWeights(cost=0.60, speed=0.40) per session; signal detection in _process_inner() adjusts ±0.05 clamped [0.2,0.8]; resets to .env defaults each boot
RATIONALE|Measured throughput (not guessed) is the only reliable basis for latency estimation; hardware varies significantly across cluster machines
RATIONALE|Latency budget as a hard raise (not soft preference) ensures the escalation chain is actually triggered when local is too slow; soft preference would be ignored under load
RATIONALE|Session-scoped weights that reset each boot prevent weight drift; if a pattern is truly useful, the NE/habit compiler should promote it to PROCEDURAL memory — that is the correct persistence mechanism
ALTERNATIVES|Rejected: fixed latency threshold with no scoring (ignores cost dimension); global persistent weights (drift without clear cause; wrong persistence layer); per-machine weight tuning (premature complexity)
TRADEOFFS|Benchmark adds ~3s of background work on first boot (hidden in daemon thread); latency estimate uses prompt_tokens as proxy which underestimates output latency — acceptable for a conservative budget gate

# ── D022 — Warm Context: Shutdown Serialization + Boot Reload ─────────────────

DECISION|id=D022|topic=warm-context|status=implemented|date=2026-03-01
TITLE|Serialize working memory to disk at shutdown; reload at boot for session continuity
CONTEXT|Ring memory and TWM persist in SQLite, but there is no explicit "here is where we were" signal surfaced at boot; sessions feel cold even though the data exists; cross-instance migration needs explicit state transfer
DECISION|_save_warm_context() at shutdown: writes TWM+ring_tail+ne_state+session_summary+current_job+timestamp to ~/.TheIgors/igor_{id}/warm_context.0.json; rotates .0→.1 first; _load_warm_context() at boot: loads .0 (fallback .1); TTL=WARM_CONTEXT_TTL_HOURS (env, default 4h); expired→archive; always injects session_summary + ne_state (if no recent narrative); injects ring_tail+TWM only if DB is empty (avoids duplicates since both persist in SQLite)
RATIONALE|Rotation (.0→.1 before writing) ensures ^C during write loses at most the current session — never the previous one; file integrity guaranteed by OS atomic rename
RATIONALE|De-duplication (ring_tail/TWM only if DB empty) is correct for the normal case (same DB resumed) and the new-instance case (fresh DB, needs full restore); both cases handled with one code path
RATIONALE|4h TTL prevents stale context from polluting a new work session started the next day; archived files are human-readable audit of prior sessions
RATIONALE|ne_state injected as category="narrative" so the NE sees it as continuity context on its first run — reduces the cold-start cognitive ramp
ALTERNATIVES|Rejected: always re-inject ring_tail (duplicates in normal resume case); never re-inject ring_tail (breaks cross-instance migration); infinite TTL (stale context next day is worse than cold start)
TRADEOFFS|JSON file is not encrypted — contains session content; acceptable for local single-user deployment; scrub.py runs on all cortex write paths before shutdown so credentials are already scrubbed

# ── D021 — Token Economy: Tool Result Capping + Turn Limit ───────────────────

DECISION|id=D021|topic=token-economy|status=implemented|date=2026-03-01

CONTEXT|Igor ran find /home/akien/TheIgors -type f | sort and accumulated 1.1M tokens across turns — hitting both OpenRouter (1M limit) and Anthropic (200K limit) hard limits, causing all upstreams to fail

RATIONALE|The truncation notice is addressed to the model ("Break large tasks into smaller steps") — it communicates the constraint and the expected response in the same message; no system prompt change required

# ── D017 — Hybrid Embedding Search in cortex.search() ────────────────────────

DECISION|id=D017|topic=hybrid-embedding-search|status=implemented|change=37
TITLE|Two-phase search: text keyword scan → embedding re-rank via nomic-embed-text
CONTEXT|cortex.search() was naive text keyword matching sorted by activation_count; poor retrieval quality for paraphrase or conceptual matches
DECISION|Phase1: text keyword scan → limit×2 candidates; Phase2: embed query + lazy-compute candidate embeddings → cosine_similarity sort; sets m.relevance_score on results; fallback to Phase1 if Ollama unavailable
RATIONALE|Phase1 (fast text scan) narrows to plausible candidates; Phase2 (semantic cosine) reranks by meaning not just lexical overlap; hybrid avoids the cold-start cost of embedding everything
RATIONALE|Lazy embedding: 422 existing memories computed on-demand as they surface as candidates; avoids a one-time ~21s blocking migration at boot; results cached to DB for future calls
RATIONALE|relevance_score field enables AnthropicReasoner to filter memories below threshold (≥0.5) rather than using top-N blindly
ALTERNATIVES|Rejected: pure embedding search (requires vectorizing all memories first; cold start on 422 entries); FAISS/vector DB (adds heavy dependency; overkill for 422-10k memories); BM25 only (better than raw keyword but still no semantic cross-vocabulary)
TRADEOFFS|First access to each memory is slower (embed compute); subsequent calls are DB-cache hits; Phase2 adds one Ollama call per search when uncached embeddings present; degrades gracefully if Ollama offline
