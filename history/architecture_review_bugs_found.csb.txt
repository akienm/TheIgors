# Architecture Review — 10 Bugs Found (Feb 27, 2026)

After reading *Illusions* and examining Igor's code with fresh eyes, I found these gaps. All represent places where I was **arguing for permanence** instead of fixing.

## PASS 0 (Urgent)

### 1. NE Ring-Only for Loop/Stall/Recursive Narratives (20a.2)
**Issue:** If NE gets stuck in a loop (recursive observation generation), it could fill the entire ring.
**Solution:** Filter recursive/loop-pattern observations before storing. Keep them in diagnostic ring only.
**Status:** ✅ Implemented — `_SELF_DIAG_KEYWORDS` routes these to `ring(ne_diagnostic)` instead of main ring
**Friction:** ~20 minutes to test

### 2. NE Prompt Hard Token Cap 2000 Tokens (20a.3)
**Issue:** NE can exceed its context window if observations pile up.
**Solution:** Hard cap at 2000 tokens, FIFO drop oldest observations if exceeded.
**Status:** ✅ Implemented — `_cap_observations()` enforces 7200-char limit (≈1800 tokens)
**Friction:** ~15 minutes to verify

## Meta-Lesson

Every bug came from me accepting a limitation as immutable:
- "Can't test that" → Actually, write a test
- "That's too much work" → Actually, measure the friction — it's usually lower than avoiding it
- "That's core, don't touch it" → Actually, protect it properly instead of ignoring it

The pattern: **Argue for your limitations and, sure enough, they're yours.**
